# Why this repository exists

Written on 2026-11-12, from Groundwork's [GW-ADR-0014](https://github.com/luckgrid/workstation/blob/main/wiki/groundwork/records/decisions/0014-shared-skills-and-agent-workflows.md) (proposed 2026-11-07), the repository's history and the kickoff kept in the owner's private project notes. The owner's words are quoted as GW-ADR-0014 records them, except that an account name is replaced by a description in brackets, since this repository is public.

## The asks (owner, 2026-11-07)

The owner wanted the Workbench guest used more for daily work: "suggest some minimal wb updates using herdr to coordinate between claude, cursor, and codex agents to handle reviews, writing code, refreshing worktrees, sharing changes with [the Mac's working account], etc... how would all this work to make it more hands off". Alongside it, shared skills: "a shared skills dotfiles using skills.sh can share skills".

The finding behind it (GW-ADR-0014's context): Codex reads skills from `~/.agents/skills` and `.agents/skills`; Cursor from those, `~/.cursor/skills` and Claude's and Codex's folders; Claude Code only from `~/.claude/skills` and `.claude/skills`. One repository installed into each harness's folder gives all three the same instructions.

## The choices (owner, 2026-11-07)

Recorded as GW-ADR-0014 decisions 1 and 2, still proposed:

- **One repository, `luckgrid/agent-skills`, public.** It holds no secrets and nothing private. Being public, the guest needs no deploy key for it. It takes over the skills part of a planned agent-config repository.
- **The skills CLI: "Pinned, local checkout only".** An exact version in a lockfile, run only from `wb setup` against the guest's local checkout of a pinned commit. The details are on [guest install](../architecture/guest-install.md).

GW-ADR-0014 also set the roles for the first review loop (Claude Code writes and fixes; Codex reviews read-only) and how text moves between agents ("Fixed prompts submit; agent text via files"). Those bind `wb-flow` in Workbench; the skills here are the fixed instructions those prompts point to.

## Creation (2026-11-09) and the guest's clone

- `luckgrid/agent-skills` was created public on 2026-11-09 with a README (initial commit `39e4eed`).
- The guest got a standing read-only clone with `wb key add agent-skills` (steps K0 to K3 passed), so `wb sync` reads it with a key although it is public.

## The kickoff for the first session (2026-11-10)

The owner's kickoff asked a Claude Code session in the guest, inside herdr, to:

1. look before changing anything, and report herdr's settings and the skill folders each harness reads;
2. propose a herdr setup in the guest's notes folder, applying only what the owner approved;
3. write the first skills: `wb-guest-rules`, `herdr` (copied from `herdr --skill`, with its licence checked), `wb-review` and `wb-remediate`; update the README; ask the owner which licence the repository should have; add `scripts/check.sh` validating the front matter with `python3`;
4. load-test the skills by hand-made links, only on the owner's word.

The rules for that session: edit only this checkout and the notes folder, commit locally only (no push credential exists in the guest; the owner promotes the branch with `wb promote` and pushes from the Mac), nothing private in a public repository, never touch credential files, install nothing, no headless agent runs, only herdr's read-only commands, and stop on any surprise. What came of it is the [first skills](2026-11-10-first-skills.md) record.
